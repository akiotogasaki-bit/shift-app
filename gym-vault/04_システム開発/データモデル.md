# データモデル（スプレッドシート構成の正本）

> **ここがこのシステムの正本。** シート名・列を変えたら、コードと同じコミットでこのファイルを更新する。
> ずれると後で必ず壊れる（CLAUDE.md 第5章）。
> サンプルデータは必ず架空名を使う。実在の会員名を書かない。

共通ルール
- 1行目はヘッダ固定。2行目からデータ。
- 日付は `YYYY-MM-DD`、時刻は `HH:mm`、日時は `YYYY-MM-DD HH:mm`（すべて文字列として保持。書式依存を避ける）
- IDは接頭辞＋連番（`M0001` `R000123`）。スプレッドシートの行番号をIDに使わない（行削除で破綻する）
- 削除はしない。`状態` 列で論理削除する

## 4. `月次残高` balances ← **サブスクの心臓部**

毎月1日に、在籍会員分の行を自動生成（GASの月次バッチ）。

| 列 | 名前 | 例 | 計算 |
|---|---|---|---|
| A | 年月 | 2027-05 | |
| B | 会員ID | M0001 | |
| C | 繰越持込 | 1 | 前月の `繰越持出` |
| D | 当月付与 | 4 | プランの月回数 |
| E | 消化 | 3 | 当月の予約で `消化=TRUE` の件数 |
| F | 残 | 2 | C＋D−E |
| G | 繰越持出 | 2 | MIN(F, プランの繰越上限) |
| H | 失効 | 0 | F−G（上限を超えて消えた分） |
| I | 締め済 | TRUE | 翌月1日に締める。締め後は書き換えない |

**なぜ残回数を予約シートから都度計算しないのか：**
都度集計は過去の予約を1件修正すると全月の残数が変わってしまう。月次で締めて確定値を持つことで、「先月の残は2回だった」という事実が動かなくなる。スプレッドシート運用では締めがないと必ず数字が合わなくなる。

## 7. `予約` reservations

| 列 | 名前 | 例 | 備考 |
|---|---|---|---|
| A | 予約ID | R000123 | |
| B | 日付 | 2027-05-10 | |
| C | 開始時刻 | 19:00 | |
| D | 個室番号 | 1 | |
| E | 会員ID | M0001 | |
| F | 状態 | 予約 / 完了 / キャンセル / 当日キャンセル / 無断欠席 | |
| G | 消化 | TRUE | 回数を消費したか。完了・当日キャンセル・無断欠席はTRUE |
| H | 登録日時 | 2027-05-01 21:30 | |
| I | 登録者 | 会員 / 妻 | |
| J | キャンセル日時 | | |
| K | 備考 | | |

**一意制約：** `日付 ＋ 開始時刻 ＋ 個室番号` で、状態が `予約` または `完了` の行は1件のみ。
→ GAS側で `LockService` を取ってから空き確認→書き込みを行う。**クライアント側のチェックだけでは二重予約が起きる。**

**キャンセル規定の実装：**
- 24時間以上前のキャンセル → 状態 `キャンセル`、消化 `FALSE`
- 24時間以内 → 状態 `当日キャンセル`、消化 `TRUE`
- 無連絡 → 妻が `無断欠席` に変更、消化 `TRUE`

## 個人情報の扱い

| データ | 機密度 | ルール |
|---|---|---|
| 氏名・連絡先 | 高 | スプレッドシートの共有は妻と社長のみ。リンク共有を絶対に有効にしない |
| `注意事項`（既往症） | **最高** | 医療情報。会員向け画面に一切出さない。設計書にも実例を書かない |
| 体重・体脂肪率 | 高 | 本人のmypageにのみ表示。他会員から見える設計にしない |
| トレーナーメモ | 高 | 妻のみ。会員向けAPIのレスポンスに含めない |

> GASのWebアプリを「全員（匿名ユーザー含む）」で公開する場合、**レスポンスに会員IDを渡すだけで他人の情報が取れる設計にしてはいけない。**
> LIFFのIDトークンをGAS側で検証し、トークンのUIDと一致する会員のデータだけを返す。
