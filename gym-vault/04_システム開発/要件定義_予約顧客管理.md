# 要件定義 — 予約・顧客管理システム

対象：完全個室マンツーマン・月額サブスク（月N回プラン）
前提：トレーナー1名（妻）／個室1室／会員上限27名（`02_料金と収支/収支シミュレーション.md` の天井）

---

## 1. 誰が何をするか

| 利用者 | 画面 | やること |
|---|---|---|
| 会員 | `reserve.html`（LIFF） | 空き枠を見る／予約する／キャンセルする |
| 会員 | `mypage.html`（LIFF） | 今月の残回数を見る／予約履歴／体組成の推移を見る |
| 妻 | `trainer.html` | 当日の予約を見る／セッション記録を入力する／欠席を記録する |
| 妻・社長 | `admin.html` | 会員の登録・状態変更／請求の締め／稼働率とチャーンを見る |

## 2. 機能要件

### 2-1. 予約（最優先・Phase 1）

| ID | 要件 | 優先度 |
|---|---|---|
| R-01 | 会員は今日から**8週間先**までの空き枠を一覧で見られる | 必須 |
| R-02 | 枠は `枠マスタ` × 日付から生成し、`休業日` と既存予約を除外して表示する | 必須 |
| R-03 | **残回数が0の会員は予約できない**（ボタンを押せない。理由を表示する） | 必須 |
| R-04 | 予約確定はサーバ（GAS）側で空き確認→書き込みを `LockService` 内で行う | 必須 |
| R-05 | 予約確定時に、会員のLINEへ確認メッセージを送る | 必須 |
| R-06 | 会員は **24時間前まで**自分でキャンセルできる。消化されない | 必須 |
| R-07 | 24時間以内のキャンセルは会員の画面からはできない（LINEで妻へ連絡。妻が `当日キャンセル` で記録し、1回消化） | 必須 |
| R-08 | 同じ日に2枠以上の予約を入れられるか → **可とする**（残回数の範囲内） | 要決定 |
| R-09 | 前日にリマインドをLINEで自動送信する | Phase 4 |

### 2-2. 会員・サブスク管理（Phase 2）

| ID | 要件 | 優先度 |
|---|---|---|
| M-01 | 妻が会員を登録し、プランを紐付けられる | 必須 |
| M-02 | 毎月1日に、在籍会員の `月次残高` 行を自動生成（前月の繰越持出を持込に、プランの月回数を付与） | 必須 |
| M-03 | 繰越は **プランの繰越上限（推奨2回）まで**。超過分は `失効` に記録して消す | 必須 |
| M-04 | 会員の状態は `在籍 / 休会 / 退会` 。休会中は回数を付与せず、予約もできない | 必須 |
| M-05 | プラン変更は旧契約を終了し新契約を追加する（行を上書きしない） | 必須 |
| M-06 | 最低継続期間（3か月）内の退会申請は、画面に警告を出す | 推奨 |
| M-07 | 残高を手で修正した場合、`操作ログ` に理由を必須入力で残す | 必須 |

### 2-3. セッション記録（Phase 3）

| ID | 要件 | 優先度 |
|---|---|---|
| S-01 | 妻がセッション後に 体重・体脂肪率・種目（種目名／重量／回数／セット）を入力できる | 必須 |
| S-02 | 入力は**スマホで片手で終わる**こと。前回の種目と重量を初期値として出す | 必須 |
| S-03 | 会員は mypage で体重・体脂肪率の推移をグラフで見られる | 必須 |
| S-04 | トレーナーメモは会員に見せない。会員向けコメントは別欄 | 必須 |
| S-05 | 記録を入力すると予約の状態が `完了` になる | 必須 |

> S-02が守られないと記録が続かない。記録が続かないと体組成の推移が出ず、**退会防止という最大の目的が達成できない。** 入力画面の作りがこの機能の成否を決める。

### 2-4. 請求（Phase 3）

| ID | 要件 | 優先度 |
|---|---|---|
| B-01 | 毎月1日に在籍会員分の請求行を生成する（月額＋前月のスポット分） | 必須 |
| B-02 | 初月は日割計算する | 推奨 |
| B-03 | `未収` の一覧を admin で見られる | 必須 |
| B-04 | 請求額を手で調整した場合、理由を必須入力する | 必須 |
| B-05 | Stripeの継続課金と連携し、決済結果を自動反映する | Phase 4 |

### 2-5. ダッシュボード（Phase 3）

`admin.html` に `00_経営/KPI.md` の5指標を表示する。

| 指標 | 計算 |
|---|---|
| 在籍会員数 | `会員` の 状態=在籍 の件数 |
| **稼働率** | 当月の 予約（状態=完了）件数 ÷ 当月の提供可能枠数 |
| 月次解約率 | 当月の 退会日 が当月の件数 ÷ 前月末在籍数 |
| 平均客単価 | 当月請求額合計 ÷ 当月平均在籍数 |
| **空き枠ヒートマップ** | 曜日×時間帯で、過去8週間の埋まり具合を色分け |

> 空き枠ヒートマップは KPI表にはないが、**稼働率を上げる実務で最も効く画面**。「火曜14時が常に空いている」が見えれば、その枠を割引にするか、営業時間から外すかを判断できる。

## 3. 非機能要件

| 項目 | 要件 |
|---|---|
| 認証 | 会員画面はLIFFのIDトークンをGAS側で検証。URLの会員IDを信用しない |
| 認可 | 会員は自分のデータのみ取得可。妻・社長の画面はGoogleアカウント制限で公開 |
| 同時実行 | 予約確定は `LockService` で直列化。二重予約を構造的に不可能にする |
| 表示速度 | 空き枠一覧の表示は3秒以内。枠生成はクライアント側で行い、GASからは予約済みリストのみ取る |
| 障害時 | **妻がスプレッドシートを直接見れば当日の予約がわかる**こと。これが最後の砦 |
| バックアップ | スプレッドシートを毎日コピーするGASトリガーを設定（30日分保持） |
| データ保持 | 退会後も会員データは論理削除で残す。物理削除は本人からの削除請求時のみ |

## 4. 画面ごとの最小仕様（Phase 1）

### `reserve.html` — 会員の予約

```
┌────────────────────────────┐
│ 今月の残り  2回（繰越1 ＋ 付与4 − 消化3）│
├────────────────────────────┤
│ ◀ 5月  ▶                    │
│ 月 火 水 木 金 土 日         │
│  …カレンダー（空きのある日に●）  │
├────────────────────────────┤
│ 5月10日（月）                │
│  10:00  ○ 予約する           │
│  11:30  × 予約済             │
│  19:00  ○ 予約する           │
└────────────────────────────┘
```
- 残0のときは全枠を押せなくし、「今月の回数を使い切りました」と表示
- 予約確定は確認ダイアログを1回挟む（誤タップ防止）

### `trainer.html` — 妻の当日画面

```
┌────────────────────────────┐
│ 5月10日（月）  3件           │
├────────────────────────────┤
│ 10:00 山田 花子             │
│   前回：スクワット40kg×10×3  │
│   [記録を入力] [欠席]        │
├────────────────────────────┤
│ 19:00 佐藤 太郎             │
│   ⚠ 腰椎に既往あり          │
│   [記録を入力] [欠席]        │
└────────────────────────────┘
```
- 注意事項（既往症）は**この画面にだけ**出す
- 前回の記録を必ず表示する（妻が思い出す手間をなくす）
